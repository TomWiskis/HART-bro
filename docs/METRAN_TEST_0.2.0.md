# Один комплексный сеанс испытаний HART-бро 0.2.0 / Метран-150

Это план, **не результаты** испытания 0.2.0. Для 0.1.1 пользователь подтвердил реальное чтение PV, близкого к нулю и совпадающего с дисплеем. Для новых команд значения заранее неизвестны.

## Подготовить до доступа к датчику

- Отдельный Android-телефон без установленного `ru.hartbro.app`: исходный ключ 0.1.1 утрачен, новый APK подписан другим debug-сертификатом. Обновление поверх 0.1.1 невозможно. Сохраните прежнюю установку; её удаление не входит в процедуру. Не меняйте application ID и не обходите проверку подписи.
- Установить APK `hart-bro-0.2.0-debug.apk` из ветки downloads; проверить SHA-256 по SHA256SUMS. `adb install -r` допустим только при отсутствии прежнего несовместимого приложения либо при повторной установке той же новой подписи. Не выполнять `adb uninstall`.
- Проверить версию 0.2.0, разрешить Bluetooth/уведомления, заранее сопрячь MACTekViator3B1F. Включить возможность сделать скриншоты и скопировать текст в локальную заметку. Приложению не нужен интернет.
- VIATOR HM-MT-BT-EX-010041, Метран-150, готовая разрешённая петля. Проверить питание/нагрузку и допустимость подключения по документации оборудования. Не разрывать рабочие измерительные цепи. Не менять настройки датчика. VIATOR не является источником питания датчика.
- Намеренный обрыв/выключение модема и испытание другого датчика — только на разрешённом лабораторном стенде. Если это невозможно, пропустить соответствующие пункты и явно записать «не проверено».

## 1. Подключение и идентификация

Открыть приложение, подтвердить выбранный VIATOR. Во вкладке «Монитор» сверить ID `9972-5FCA7F`, Метран (0x0099), HART 7, ревизии ПО 40 / устройства 7. Сделать скриншот. Убедиться в наличии системного уведомления мониторинга.

## 2. Все доступные переменные и сверка PV

Дождаться нескольких циклов. Записать для каждой PV/SV/TV/QV: значение, единицу и её код, classification, variable code, quality/raw status, команду-источник. Если слот не поддерживается или качество плохое, он не должен выглядеть как достоверный ноль. Не приписывать SV/TV физический смысл без данных прибора.

Сверить PV с дисплеем Метрана. При нулевом перепаде допустимо небольшое колеблющееся значение около нуля; **не ожидать постоянно −0.01330386**. Это значение предыдущего кадра, не эталон и не генератор данных. Ток из команды 3 считать только диагностическим значением датчика, не независимым измерением. Сделать скриншот значений и один скриншот графика.

Открыть HEX и сразу скопировать журнал первоначального подключения: 0, 1, 8/50/48/3, 9 и реальные ответы. Сохранить в локальную заметку с временем. Буфер ограничен 512 событиями, длинный 5-минутный обмен вытеснит начальные кадры. Ожидаемы четыре FF с предупреждением; успешный кадр должен пройти XOR. Ответ «не поддерживается» должен приводить к переходу на 3 или 1, без циклического повторения неподдерживаемой команды и без объявления датчика неисправным.

## 3. Периоды, пауза и единый график

Провести около пяти минут мониторинга. Проверить 2 с по умолчанию, затем 1/5/10 с и вернуть 2 с. Если обмен медленнее периода, запросы должны оставаться последовательными, без пачки «догоняющих» команд. По HEX записать фактическое время обмена.

Скрыть/показать линии легендой; увеличить/уменьшить масштаб кнопками и жестом, переместиться ползунком/жестом, выбрать точку и сверить её точное значение/время/единицу, включить следование. Все серии должны быть на одном графике с разными шкалами Y, без пересчёта физических единиц.

Поставить паузу на 10–15 с. Текущее значение должно перестать считаться актуальным. После продолжения должны появляться новые timestamps и новый сегмент, без нуля, повторения прежнего значения и соединения через паузу. Сделать скриншот разрыва.

## 4. Фон и экран

Свернуть приложение на 30–60 с, заблокировать экран ещё примерно на минуту. Уведомление должно остаться; после возврата проверить timestamps/график за это время. Если Android ограничил процесс, записать производителя телефона, настройки энергосбережения и поведение, не выдавать это за успешный фон. Скриншот уведомления и графика после возврата.

## 5. Ручной архив

Нажать «Сохранить сессию», дождаться подтверждения, открыть «Журнал», проверить ID/время/график/разрыв паузы. Вернуться к мониторингу, получить новые точки, сохранить второй снимок. Первый снимок должен остаться неизменным, второй — содержать более поздние точки.

Удалить один тестовый снимок: сначала отменить диалог и убедиться, что запись осталась, затем подтвердить удаление. Другой снимок должен сохраниться. При обычном завершении выбрать «Завершить без сохранения»: временная история исчезает, ранее сохранённый снимок остаётся. Повторно открыть приложение и проверить постоянный архив.

## 6. Краткий Bluetooth-разрыв — лабораторный пункт

В рамках новой подтверждённой сессии вызвать допустимую краткую потерю связи с VIATOR, не трогая рабочую петлю. Проверить статус потери, очистку текущих значений, попытки восстановления к тому же модему без нового подтверждения. Вернуть модем до 60 с. В HEX после восстановления должна быть команда 0 и совпадающий ID; затем новые измерения той же сессии и разрыв линии. Сразу скопировать журнал и сделать скриншот графика.

Если безопасно можно проверить отсутствие HART при сохраняющемся Bluetooth, убедиться, что единичная ошибка не разрывает RFCOMM; подтверждение потери — после трёх подряд ошибок. Не отключать технологический датчик специально вне лаборатории.

## 7. Таймаут 60 секунд — лабораторный пункт

Вызвать потерю, удерживать её дольше минуты. Отсчитывать от сообщения «Связь потеряна», а не от первой единичной ошибки. После общего интервала 60 с должны прекратиться попытки и появиться выбор «Сохранить сессию» / «Завершить без сохранения», без автоматического действия. В фоне должен быть запрос решения в уведомлении, без принудительного открытия окна.

Один раз выбрать сохранение: открыть архив и проверить разрыв/событие таймаута. Если доступ позволяет, во второй короткой сессии повторить таймаут и выбрать завершение без сохранения: новой архивной записи не должно быть. Ранее сохранённая запись должна остаться.

## 8. Другой прибор — только при доступности второго разрешённого датчика

В процессе восстановления предоставить ответ другого HART ID. Приложение должно остановить объединение данных и предложить сохранить/завершить старую сессию. Новая сессия требует отдельного подтверждённого подключения. Если второго прибора нет, отметить «на аппаратуре не проверено»; программный сценарий выполнен автоматически.

## Что передать одним сообщением

- Модель телефона/Android и условия петли; какие пункты пропущены и почему.
- Скриншоты ID, всех переменных, графика с разрывом/легендой, уведомления, архивной записи и диалога таймаута.
- Текст HEX первоначального подключения, короткого восстановления и таймаута, скопированный сразу после соответствующего события (три отдельных фрагмента).
- Для каждого слота значение/единица/quality/source, сопоставление PV с дисплеем и реальные длительности обмена.
- Результаты паузы, фона, двух ручных сохранений/удаления и сохранности архива после перезапуска.

Команды записи, 38, калибровка, смена диапазонов/назначений/тока и USB **не испытываются**. Успех этого сеанса не означает сертификацию приложения или подтверждение полной исправности оборудования.
