# Одно комплексное аппаратное испытание 0.3.0

Использовать тот же телефон Android 16, VIATOR и Метран-150 HART 7 (manufacturer 0099, type 9972, ID 5FCA7F). Другой экземпляр прибора допустим, но ожидаемый ID необходимо записать до испытания. Никаких операций записи, сброса статусов, калибровки или изменения диапазона приложением не выполнять.

## Подготовка и обновление

1. На 0.2.1 вручную сохранить важную текущую сессию; записать количество архивов, открыть один архив и запомнить его дату/точки.
2. Установить **опубликованный APK 0.3.0** поверх 0.2.1, без удаления приложения/очистки данных. Допустимо `adb install -r hart-bro-0.3.0-debug.apk`. applicationId и сертификат совпадают с опубликованными 0.2.0/0.2.1; APK из произвольного CI-run может иметь другой debug-сертификат.
3. Проверить версию 0.3.0, доступность прежних архивов и их графиков. У старого архива конфигурация/диапазон могут отсутствовать: должно быть «Нет данных»/«Диапазон неизвестен», а не новые настройки текущего прибора.
4. Разрешить Bluetooth/уведомления. Сопряжение VIATOR выполнить штатно. При необходимости записать настройки энергосбережения телефона, чтобы условия опыта были воспроизводимы.
5. Сохранить прежний нужный HEX в TXT, затем явно очистить рабочий HEX. Подробный RX-CHUNK оставить выключенным в длительных интервалах; кратко включить отдельно при необходимости исследования фрагментации. Записать время начала испытания.

## Связь без сессии

6. Подтвердить подключение к VIATOR. Проверить правильный ID и состояние «Можно начать сессию». До нажатия «Начать сессию» не должны расти график, длительность или архивы. Единичные команды идентификации/конфигурации допустимы.
7. Проверить TAG/описание, доступный снимок конфигурации и компактную строку диапазона. Сравнить диапазон команды 15 с заранее известными настройками Метрана или независимым доверенным чтением. Приложение не должно вычислять его из текущего давления/тока. При недоступной 15 должно быть «Диапазон неизвестен», остальные доступные функции продолжают работать.
8. Повторить отдельное первоначальное подключение с уходом Home/в другое приложение сразу после подтверждения. Вернуться после завершения идентификации; должна быть та же попытка и готовность либо конкретная диагностируемая ошибка, без выдуманной сессии. При неуспехе сохранить полный HEX, восстановить условия петли/модема и подключиться штатно. Не приписывать сбой FGS без событий SERVICE/PROCESS.

## Мониторинг и фон

9. Нажать «Начать сессию», проверить новую дату начала, ID, поступление PV/SV/TV/QV с фактическими единицами/качеством. Команда 9 на Метране должна продолжать работать; прошлые временные fallback-настройки новой сессии не наследуются.
10. Наблюдать **5 минут с включённым экраном**. Проверить числовые оси, значения точек, выбор/скрытие совпадающих серий, масштаб, ручной сдвиг, автоследование с сохранением масштаба и «Вся сессия». Справа над графиком — одна строка настроенного диапазона, не физические пределы сенсора.
11. Выключить экран **на 5 минут**. После возврата проверить не только уведомление, но и фактические измерения за интервал блокировки и сохранение той же даты начала/ID.
12. Открыть браузер/Telegram/другое приложение **на 5 минут**. Вернуться и проверить фактическую непрерывность по временным меткам истории. Несколько раз перейти Home → другое приложение → HART-бро; не должно появляться новых сессий/повторных Bluetooth-подключений при исправном сокете.
13. Нажать «Приостановить», подождать 15 секунд, затем «Продолжить». Bluetooth и ID сессии сохраняются; новых измерений в паузе нет, на графике реальный разрыв.
14. В контролируемых безопасных условиях кратко убрать HART-ответы (без записи в датчик), затем восстановить их. Проверить таймауты/события, единый отсчёт максимум 60 секунд и восстановление с проверкой ID. Отдельно при возможности проверить кратковременную потерю Bluetooth: повторное подключение допустимо только при неисправном/закрытом сокете. Прибор не должен смешиваться с другим ID.
15. Если работа прервалась, записать точное время действия/состояния/фазы. Не очищать HEX: сохранить его целиком вместе с наблюдениями. Сопоставить ACTIVITY, SERVICE, BLUETOOTH, STATE, lastTX/lastRX/lastMeasurement и длительность отсутствия данных. Не заявлять внешнюю причину на основании одного таймаута.

## Журнал и отчёты

16. Во время продолжающегося опроса нажать «Сохранить сессию» дважды с интервалом 10–15 секунд. Должны появиться два самостоятельных снимка, опрос не должен останавливаться. Их время окончания/длительность различаются.
17. Открыть журнал, проверить компактные поля, поиск по TAG/ID/названию и сортировку. Переименовать одну проверку, добавить многострочный кириллический комментарий. Переоткрыть запись, убедиться в сохранности названия/комментария/графика.
18. Прокрутить длинную проверку: закреплённое «К списку» и системная «Назад» должны возвращать в список; переходы вкладок не завершают мониторинг.
19. Сохранить PDF через выбор файла Android; отдельно проверить «Отправить PDF». Открыть в независимом просмотрщике и проверить A4/кириллицу, дату, название, производителя/type/ID/TAG/HART/range/VIATOR, длительность, единицы, min/max/средние/количества GOOD и UNVERIFIED, график с числовыми шкалами/временем/легендой и разрывами, события и комментарий. Плохие/отсутствующие данные не должны превращаться в нули или достоверные статистические точки.
20. Сохранить/отправить CSV с `;`, затем при необходимости с `,`. Импортировать как UTF-8, выбранный разделитель, десятичная точка. Проверить UTC, отрицательные и дробные значения без округления, коды единиц, качество, номер команды. Сравнить выбранные исходные точки с историей; количество строк должно отражать все измерения, а не сокращённые точки графика.
21. Сравнить два снимка одной сессии и один снимок с текущей конфигурацией. Отличия текущих давления/температуры не должны считаться изменением конфигурации. В сравнении старого архива с новым отсутствие поля — «Нет данных», без ложного выделения изменения. Для проверки различий настроек можно использовать ранее сохранённые проверки с действительно разными доступными настройками, не изменяя датчик этим приложением.
22. Проверить отдельное и множественное удаление на **специально созданных ненужных копиях**, сначала отменить подтверждение, затем подтвердить. Убедиться, что другие записи и экспортированные файлы не удалились. Проверку «Очистить весь журнал» выполнять только при отсутствии ценных записей; достаточно проверить диалог и отменить, если их нельзя удалять.

## Следующая сессия и завершение

23. Завершить текущую сессию с сохранением. Bluetooth может оставаться подключённым, кнопка «Начать сессию» снова доступна. Начать вторую сессию без нового подтверждения исправного VIATOR. Проверить повторную команду 0 перед новой историей и отдельные начало/ID временной записи.
24. По возможности, завершив вторую сессию, безопасно переставить щупы на другой известный HART-датчик и вручную начать новую. Новая история должна относиться к фактическому новому ID; смешения данных быть не должно. Автоматический обход приборов не ожидается.
25. Завершить ненужную пробную сессию без сохранения: новая постоянная запись не появляется, прежние архивы сохраняются. Отдельно отключить коммуникатор. После force-stop автоматического рестарта не ожидается.
26. Сохранить полный HEX вручную: он должен содержать первоначальную команду 0, доступные чтения 13/15/20/48/50, измерительные команды, времена ответов, события Android/сессий/сокета и причины ошибок. Отметить, не был ли достигнут лимит; при предупреждении неполный файл не считать полным опытом.

## Что прислать после одного комплексного испытания

Версию Android/модель телефона, ID/настройки прибора, версии приложения до/после установки, результат сохранности старых архивов; отметки времени трёх пятиминутных интервалов и перехода во время подключения; полный HEX TXT; один PDF и CSV, название/комментарий проверочной записи; конкретные несовпадения/ошибки и ожидаемые значения диапазона. Адрес Bluetooth и ID находятся в диагностике — передавать файлы осознанно.
