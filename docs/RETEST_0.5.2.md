# Испытание APK 0.5.2

Это сценарий на физическом приборе; автоматические результаты перечисляются отдельно в VALIDATION_0.5.2.md.

1. Сохранить важную текущую сессию/ведомость и установить подписанный APK поверх 0.5.1 без удаления приложения и очистки данных. Проверить прежние сохранённые записи, ведомости и экспорт.
2. Выбрать VIATOR и подтвердить подключение. На всех вкладках проверить имя/значок в заголовке, включая длинное имя. После HART-идентификации проверить нейтральное имя с ID, если модель не имеет документированного соответствия. Нельзя считать Device Type названием модели.
3. Начать сессию. Проверить цифровой PV и отдельно ток, полученный HART-командой 3; если она недоступна, ожидается «Нет данных». Сравнить с реальными показаниями прибора. Дополнительных подставленных PV/SV/TV/QV быть не должно.
4. Наблюдать больше минуты: окно остаётся 60 с. Прокрутить в прошлое, изменить масштаб, сменить вкладку, повернуть экран. Масштаб/окно сохраняются. Вернуться ползунком/жестом вправо: следование включается без обязательной кнопки. Старые данные доступны; диапазон прибора находится справа над графиком и не меняется при масштабировании.
5. Открыть диагностику: это отдельный экран с новыми чтениями. Проверить один Device Type, защиту записи понятным текстом, отсутствие даты чтения и самостоятельного 0x40. Остальные переменные показываются только при реальной поддержке. Вернуться: прежняя сессия продолжается, соединение не дублируется.
6. Открыть диапазон: первые символы заменяют выделенные числа, работают минус/запятая/вставка, кнопки знака и обычное повторное исправление. Текущая единица выбрана сразу. Без документированного профиля список содержит только эту единицу — это ожидаемое ограничение, не ошибка интерфейса.
7. Проверить отмену отдельного подтверждения — передачи 35 нет. Для разрешённой настройки использовать существующий HARDWARE_TEST_0.5.0.md: одна 35, затем проверочное чтение 0/15. Потерянный ответ не должен приводить к повторной записи. Конкретный результат и воздействие на токовый выход нельзя подтвердить программным имитатором.
8. Проверить компактную запись изменения: дата одна, параметры строками, подтверждённый успех ✓, отрицательный результат ✕, неопределённость ?. Открыть подробности. Удалить одну запись и всю историю после подтверждения: конфигурация датчика остаётся прежней, новых HART-команд из-за удаления нет.
9. Снять щупы и отдельно прервать Bluetooth: HART-отказ и Bluetooth-разрыв должны различаться. Старые показания помечаются неактуальными, новые точки отсутствуют, линия разорвана. «Переподключение · N с» видимо только во время попыток, по окончании 60 с исчезает. После восстановления нет искусственного соединения линии через пропуск. Проверить повтор 0.5.1 и запрет объединения другого ID.
10. На узком экране и крупном шрифте проверить заголовок, полные значения, две границы/единицы, подписи времени, историю и доступность всех действий. Сохранить HEX-журнал и снимки интерфейса при отклонении от ожидаемого.
