# Первое испытание с реальным VIATOR

## Подготовка

Испытание проводит инженер на отдельной лабораторной петле, вне действующей автоматики. Используйте инструкции датчика и VIATOR по питанию, подключению, нагрузке, искробезопасности и условиям применения. Приложение само не подтверждает пригодность телефона/петли для взрывоопасной зоны.

1. Подготовьте VIATOR **HM-MT-BT-EX-010041**, его руководство, Android-телефон 10+ с Bluetooth Classic, HART-датчик давления или температуры, питание и требуемую HART-нагрузку.
2. Убедитесь, что датчик имеет **polling address 0** и стабильно отвечает штатному коммуникатору. Прототип не меняет адрес и не ищет адреса 1–63.
3. По официальному руководству проверьте режим SPP/прозрачной передачи и необходимость инициализации вашей версии прошивки VIATOR. Не вводите случайные управляющие или AT-команды.
4. Установите debug APK по README. Запишите версию APK, модель телефона, Android, модель/ревизию датчика и VIATOR для отчёта.

## Соединение

1. Включите VIATOR и выполните сопряжение через системные настройки Bluetooth. Если нужен PIN, используйте только указанный в руководстве производителя; прототип PIN не угадывает. Завершите системный поиск устройств перед подключением: прототип не запрашивает `BLUETOOTH_SCAN` и не отменяет обнаружение, запущенное другими приложениями; оно может замедлить соединение.
2. Откройте приложение. На Android 12+ нажмите «Разрешить Bluetooth» и предоставьте разрешение «Устройства поблизости». На Android 10–11 отдельный runtime-запрос для чтения списка сопряжённых устройств не нужен.
3. Приложение читает список сопряжённых устройств, но **не подключается автоматически**. Если найден ровно один VIATOR, появляется диалог согласия. При нескольких выберите нужный по имени и адресу. Если модем переименован, включите показ других сопряжённых устройств.
4. При необходимости нажмите «Обновить список», затем «Подключить…». До нажатия «Продолжить подключение» RFCOMM и HART-обмена быть не должно.
5. После согласия ожидаются подключение SPP (до 15 с), команда 0 на короткий адрес 0, затем команда 1 по идентифицированному длинному адресу. На HART-чтение отводится до двух попыток по 2,5 с.

## Что проверить

- Отмена диалога не устанавливает соединение.
- На вкладке «Результат» отображаются ревизия HART, уникальный адрес, код производителя/типа, статус и цифровая PV с единицей и временем приёма.
- Сравните PV и единицу с независимым HART-коммуникатором. Измените входную величину на стенде и нажмите «Считать снова» — должно прийти новое фактическое значение. Ток 4–20 мА для пересчёта не используется.
- На вкладке HEX присутствуют TX команды 0 с коротким адресом, RX с корректным кодом ответа и TX команды 1 с длинным адресом. Сырой RX может быть разбит на несколько событий. В успешном логе HART код ответа равен 0; ненулевой device status не скрывается.
- Отключите датчик от тестовой петли и повторите чтение: нет достоверного нового значения, есть ошибка/таймаут и HEX. Восстановление автоматически не выполняется на этапе 1.
- Завершите соединение кнопкой, проверьте повторное подключение с новым согласием. Сверните приложение: соединение должно закрыться; после возврата данные не должны выдаваться за новое измерение.
- Проверьте поворот экрана и отказ в разрешении: приложение не должно падать или начинать незапрошенный обмен.

## Как собрать диагностику

Откройте HEX и нажмите «Копировать диагностику» только по своему решению. Скопированный текст содержит время, Android/API, реальные TX/RX, коды ошибок, адрес Bluetooth и идентификатор датчика. Перед передачей проверьте, кому можно раскрывать эти сведения. Последние 256 событий находятся только в памяти, не в постоянном журнале; завершение процесса их удалит.

К логу добавьте сведения о стенде, серийной версии VIATOR/прошивки (если доступны), датчике, его HART-ревизии, polling address, подтверждённой работоспособности петли и точной последовательности действий. Текст ошибки можно скопировать вместе с HEX. Если нужны системные сведения, используйте `adb logcat` отдельно; это не требуется для обычного чтения.

## Типовые ошибки

| Признак | Следующее действие |
| --- | --- |
| VIATOR отсутствует в списке | Проверить системное сопряжение; обновить список; показать устройства без имени VIATOR. Поиск в эфире внутри приложения не реализован. |
| Нет разрешения | Разрешить «Устройства поблизости» в настройках приложения. После постоянного отказа системный диалог может больше не появляться. |
| Bluetooth выключен/недоступен | Включить штатным диалогом; проверить наличие Bluetooth Classic на телефоне. |
| Отказ/таймаут RFCOMM | Проверить питание, расстояние, сопряжение, отсутствие второго клиента, поддержку secure SPP и режим VIATOR по его документации. |
| Есть TX, но нет RX | Проверить петлю, нагрузку, адрес 0, роль primary master, прошивку/режим модема и его требования к инициализации. Это **не** успешный HART-сеанс. |
| RX есть, но неверны сумма/длина | Сохранить диагностику; проверить помехи, фрагменты и формат передачи модема. Не считать произвольные байты измерением. |
| Ответ игнорируется | Сравнить адрес и номер команды; эхо, burst и ответы другой команды не принимаются как ожидаемый ACK. |
| Ненулевой код ответа | Зафиксировать код и статус; команды записи не добавлять для обхода ошибки. |
| Неизвестные модель/единицы | Передать исходный ответ и официальное описание прибора. Не подставлять похожий профиль. |

**Критерий аппаратной приёмки этапа 1:** реальный VIATOR устанавливает соединение, датчик возвращает корректные HART-ответы 0 и 1, приложение показывает подтверждённую цифровую PV. В облачной среде без телефона, VIATOR и петли этот критерий проверить невозможно. Не отмечайте его выполненным по результатам JVM-тестов или одной сборки APK.
