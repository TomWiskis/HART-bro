# ТЗ: Доработка HART-Бро 0.5.x

## 1. Общая задача

Доработать текущую версию Android-приложения HART-Бро перед переходом к интеграции USB-устройства ЭнИ-406.

Основные задачи:
- Улучшить идентификацию подключённых датчиков.
- Реализовать полноценное редактирование параметров.
- Добавить установку нуля через HART.
- Разделить быстрое чтение конфигурации и полноценную измерительную сессию.
- Исправить поведение графиков и индикации соединения.
- Доработать диагностическое окно и журнал изменений.

Сохранить существующую архитектуру приложения и визуальный стиль. Не выполнять преждевременную интеграцию USB.

---

## 2. Карточка быстрого просмотра датчика

Это основной экран для быстрой проверки датчика при наладке.

### Компоновка

**Первая строка:**
- Слева индикатор состояния датчика.
- Производитель и расшифрованная модель.
- TAG в скобках сразу после модели.

**Вторая строка:**
- Серийный номер (Device ID) в десятичном виде.
- Дата производства.
- Оба значения отображаются только цифрами, уменьшенным шрифтом, непосредственно под производителем и моделью.
- Без подписей и названий полей.

Если какого-либо значения нет, оно просто не отображается. Не оставлять пустые места, подписи или заглушки.

**Правая часть карточки:**
- Диапазон измерения с единицами.
- Слева от диапазона небольшая кнопка с изображением карандаша.

**Кнопки:**
- По центру под информацией — «Установить ноль».
- Следом — «Начать измерительную сессию».

Вертикальный отступ между информационной частью и кнопками минимальный.

### Взаимодействие

- Вся информационная строка карточки кликабельна, кроме области редактирования диапазона.
- Нажатие на неё открывает полноценное диагностическое окно датчика.
- Редактирование диапазона не должно вызывать переход в диагностику.
- Кнопка установки нуля запускает соответствующую процедуру HART.
- Кнопка измерительной сессии открывает полноценный режим мониторинга с графиками.

### Индикация состояния

- Зелёный индикатор — датчик успешно опрошен и периодически выходит на связь.
- Красный индикатор — датчик не отвечает.

Отсутствие активной измерительной сессии само по себе не является причиной показывать красный статус.

---

## 3. Быстрое чтение и фоновый опрос

Не нужно каждый раз открывать полноценную измерительную сессию.

В режиме быстрого просмотра необходимо считывать:
- Производителя.
- Модель (Device Type).
- Device ID — серийный номер.
- Дату производства.
- TAG.
- Диапазон измерения.
- Доступные параметры конфигурации.

Не отображать в быстрой карточке:
- Версию HART.
- Текущую измеряемую величину.
- Текущий ток.

После первоначального чтения сохранять информацию на экране.

В фоновом режиме выполнять лёгкую проверку наличия устройства и его Device ID примерно раз в 1–2 секунды. Это необходимо для обнаружения замены датчика.

При обнаружении нового Device ID повторно считывать конфигурацию и обновлять карточку.

Не выполнять постоянный опрос PV и тока вне измерительной сессии.

Если измерительные показания не запрашиваются, не нужно создавать для них состояние «неактуальные».

### Важное ограничение

Существующий режим «Обход датчиков» не изменять. Он предназначен для последовательного сбора данных в таблицы и должен сохранить прежнюю логику.

---

## 4. Идентификация производителей и устройств

Необходимо добавить таблицы идентификации HART-устройств.

Реализовать расшифровку:
- Manufacturer ID — производитель.
- Device Type — модель устройства.

В интерфейсе вместо необработанных идентификаторов отображать понятные названия.

Предусмотреть возможность расширения таблиц и добавления новых производителей и моделей.

Для неизвестных устройств сохранять возможность отображения исходных идентификаторов.

Device ID считать серийным номером и отображать в десятичной форме.

Final Assembly Number считывать и показывать только при наличии реального значения. Если параметр отсутствует, не создавать под него пустую строку или ячейку.

---

## 5. Редактирование параметров датчика

Реализовать возможность записи поддерживаемых датчиком параметров:

- TAG.
- Meter ID.
- Date.

Не путать Meter ID с Device ID: Device ID является серийным номером устройства.

Перед каждой записью сохранять существующий механизм подтверждения:
1. Изменение значения.
2. Подтверждение пользователем.
3. Запись в датчик.
4. Повторное чтение для проверки результата.

Не показывать запись как успешную, если повторное чтение не подтвердило изменение.

### Редактирование диапазона

Редактор должен быть компактным.

- Нижняя и верхняя границы располагаются в одной строке.
- Между ними используется разделитель «-».
- Справа располагается список единиц измерения.
- При открытии редактора автоматически выбирается текущая единица датчика.
- При вводе первого нового символа старое значение соответствующего поля полностью очищается.

Предоставить возможность выбрать любую единицу измерения. Если датчик не поддерживает выбранную единицу, он не должен получать некорректную запись.

---

## 6. Установка нуля

Добавить функцию установки нуля через HART.

Назначение: при нулевом давлении датчик должен показывать нулевое значение.

Это особенно важно для датчиков, у которых отсутствует физическая кнопка установки нуля.

Использовать поддерживаемую датчиком стандартную или предусмотренную производителем HART-команду.

Перед выполнением операции:
- Проверить возможность выполнения операции для конкретного устройства.
- Запросить подтверждение пользователя.
- Выполнить команду.
- Повторно прочитать значение и проверить результат.

Не отправлять неподдерживаемые команды вслепую.

Кнопка «Установить ноль» должна находиться в карточке быстрого просмотра на согласованном месте.

---

## 7. Диагностика датчика

Кнопку «Открыть диагностику» сохранить.

Разместить её рядом с данными датчика в верхней части страницы мониторинга.

При нажатии должно открываться полноценное диагностическое окно HART, а не HEX-вкладка.

Диагностика должна предоставлять:
- Идентификационные данные.
- Конфигурацию датчика.
- Список доступных HART-параметров.
- Статусы и коды ошибок.
- Возможность редактирования поддерживаемых параметров нажатием на соответствующую строку.

Не дублировать Device Type на одной странице.

Убрать переменную 0x40 из пользовательского отображения.

В строке защиты записи убрать пояснение «по данным команды 15».

Дату последнего прочтения данных на странице не показывать: она не нужна при каждом открытии окна.

---

## 8. Измерительная сессия и мониторинг

Полноценная измерительная сессия запускается только по кнопке «Начать измерительную сессию».

В основном мониторинге оставить только:
- Измеряемую величину (PV).
- Ток датчика.

Остальные параметры перенести в диагностическое окно.

Увеличить время ожидания обновления измерительных данных, чтобы исправить постоянное отображение сообщения «неактуальные показания» для тока.

Не объявлять данные устаревшими раньше фактического истечения увеличенного времени ожидания.

### Индикация HART

В верхней части мониторинга вместо надписи «Ответ HART получен» показывать:
- Название датчика.
- Зелёную галочку при стабильном успешном обмене.

При потере обмена:
- Красный крестик.
- Уведомление о переподключении.
- Оставшееся время до окончания попыток.
- Коды ошибок.

Время таймаута показывать только во время активных попыток переподключения, рядом с надписью «Переподключение».

---

## 9. Bluetooth-индикация

Справа от надписи «HART-Бро 0.5.1» разместить компактную индикацию Bluetooth-соединения.

Отображать:
- Значок состояния соединения.
- Короткое имя подключённого Bluetooth-устройства.

Состояние должно обновляться автоматически:
- При подключении.
- При отключении.
- При смене подключённого устройства.

Если соединение потеряно во время работы, немедленно изменить индикатор.

Не путать состояние Bluetooth-соединения с состоянием обмена HART: это два отдельных статуса.

Таймер переподключения показывать только в период активных попыток восстановления связи.

---

## 10. График и временная шкала

Исправить работу графика и бегунка временной шкалы.

### Стандартное поведение

- При запуске измерительной сессии включено следование за текущим временем.
- Используется стандартный масштаб отображения.
- При поступлении новых данных график автоматически перемещается вперёд.
- Если длительность записи превышает видимый масштаб, более старые данные вытесняются новыми из отображаемого окна.

### Ручное перемещение

- При ручном перемещении графика пользователем автоматическое следование отключается.
- График остаётся в выбранном пользователем временном положении.
- Новые данные не должны принудительно возвращать график к настоящему времени.
- Масштаб временного окна при перемещении остаётся неизменным.

### Изменение масштаба

- Пользователь должен иметь возможность изменять масштаб вручную.
- Изменение масштаба не должно блокировать ручное перемещение графика.
- Не должно происходить самопроизвольного включения следования при изменении масштаба.

### Возвращение к настоящему времени

При перемотке графика к текущему времени автоматически включать следование.

После этого график снова должен перемещаться за поступающими данными.

---

## 11. Журнал изменений

Сделать историю изменений более компактной.

Каждая запись должна содержать:
- Слева — дату.
- По центру — список изменений.
- Справа — результат проверки.

Каждое новое изменение размещать на отдельной строке внутри записи.

Результат проверки отображать символами:
- Зелёная галочка — успешная проверка.
- Красный крестик — неуспешная проверка.

Предусмотреть возможность удаления отдельных записей из журнала.

---

## 12. Визуальные ограничения

Сохранить нынешний дизайн приложения.

Не заниматься дополнительной косметической переработкой:
- Не менять общую стилистику.
- Не перестраивать уже согласованные страницы.
- Не добавлять лишние информационные поля.
- Не увеличивать количество отображаемых параметров без необходимости.

Приоритет — функциональность, стабильность обмена и корректность работы с датчиками.

---

## 13. Проверка и результат

После реализации:

1. Проверить чтение идентификационных данных.
2. Проверить расшифровку Manufacturer ID и Device Type.
3. Проверить отображение Device ID и даты производства.
4. Проверить чтение и запись TAG, Meter ID и Date.
5. Проверить изменение диапазона и единиц измерения.
6. Проверить установку нуля на поддерживаемом устройстве.
7. Проверить фоновое обнаружение смены датчика.
8. Проверить переход из быстрого просмотра в диагностику и измерительную сессию.
9. Проверить стабильность обмена и индикацию потери соединения.
10. Проверить график при автоматическом следовании, ручной прокрутке и изменении масштаба.
11. Проверить журнал и удаление записей.
12. Проверить, что режим обхода датчиков сохранил прежнее поведение.

По завершении собрать APK для испытаний и предоставить перечень выполненных изменений и оставшихся ограничений.

---

## 14. Что не входит в эту задачу

**USB-интеграция ЭнИ-406 (mini-USB) полностью исключается из текущего этапа.**

Её реализация будет оформлена отдельным следующим ТЗ после проверки текущей версии.

Не начинать USB-разработку параллельно с перечисленными изменениями.
