# Метран: единый сеанс испытания 0.1.1

Цель — за один доступ к лабораторной петле проверить исправленный приём команды 0, переход на уникальный адрес, реальную PV, единицы/статусы и управляемое завершение. Никакие настройки датчика не изменяются. Команд записи, калибровки, сброса состояния и USB-транспорта в этой сборке нет.

## До получения доступа к оборудованию

1. Скачайте `hart-bro-0.1.1-debug.apk` из ветки `downloads` GitHub. Установите поверх 0.1.0: package name прежний, versionCode увеличен. При открытии на верхней панели должна быть версия **0.1.1**. Вставленный в буфер HEX также должен начинаться с `HART-бро 0.1.1`.
2. Подготовьте место для вручную скопированного лога. Он содержит адрес Bluetooth и ID датчика. Данные остаются в памяти и пропадут при завершении процесса Android; автоматического постоянного журнала нет.
3. Проверьте системное разрешение Bluetooth и имеющееся сопряжение VIATOR. Завершите поиск устройств в системных настройках, чтобы он не замедлял SPP. Подготовьте отдельную питаемую лабораторную HART-петлю с нужной нагрузкой и polling address **0**, согласно руководствам оборудования.

## Сеанс на стенде

| Шаг | Действие | Что зафиксировать |
| --- | --- | --- |
| 1 | Открыть HEX и очистить прежние события, выбрать VIATOR и подтвердить соединение. | До подтверждения HART-обмена нет; после него начинается команда 0. |
| 2 | Дождаться идентификации. | Для датчика из присланного дампа: **HART 7**, **Метран (0x0099)**, тип **0x9972**, ID **5FCA7F**, ревизия команд устройства 7, ПО 40, аппаратная ревизия 1. Другой ID означает другой прибор; приложение читает поля ответа, не подставляет эти значения. |
| 3 | Проверить HEX команды 0. | Есть один полный `RX-FRAME`, независимо от числа `RX-CHUNK`. Для того же ответа длина payload `0x18`, статус `00 00`, XOR `65`. Четыре `FF` дают `WARN`, но не отказ и не таймаут. Пять и более `FF` предупреждения не требуют. |
| 4 | Дождаться автоматического **разового** чтения команды 1. | `TX-FRAME` имеет разделитель `82` и адрес **99 72 5F CA 7F** для указанного датчика. В принятом ACK — команда `01`, цифровая PV, её единица и фактическое время получения. Сопоставить значение с независимым цифровым HART-показанием, если оно доступно. |
| 5 | Нажать «Считать снова» два раза, каждый раз дождавшись ответа. | Новые реальные `TX-FRAME`/`RX-FRAME`, соответствующие временные метки, читаемое название единицы и исходный код HART. Между нажатиями приложение не генерирует новые значения. Ненулевой device status расшифровывается, а не сбрасывается. |
| 6 | Повернуть экран при установленной связи. | ID и соединение сохраняются, показание само не меняется. Скопировать диагностический лог до проверки обрыва. |
| 7 | Только на лабораторном стенде безопасно разомкнуть HART-связь с датчиком, оставив VIATOR доступным; нажать «Считать снова». | Не более двух попыток чтения, затем явная ошибка; старое значение не выдаётся за новое. Неполный ответ, если он поступил, виден в диагностике. Записи и автоматического восстановления нет. |
| 8 | Восстановить петлю, вручную повторно подключиться с подтверждением. | Повторная команда 0, тот же ID, затем корректная PV команды 1. Скопировать итоговый лог. |
| 9 | Свернуть приложение и вернуться. | Соединение закрыто — это ожидаемое ограничение этапа 1. Для нового подключения снова требуется подтверждение. |

Если времени мало, приоритетны шаги 1–5 и итоговый полный лог. При невозможности безопасно разомкнуть лабораторную петлю шаг 7 пропустите и укажите это в отчёте. Не испытывайте обрыв на действующей автоматике.

## Если команда 0 проходит, а PV не получена

Не требуется повторять всё испытание многократно. Скопируйте один лог с полным ответом 0, полным запросом 1, всеми полученными фрагментами и ошибкой. Отметьте, какая единица настроена на датчике, его точную модель, HART-ревизию и версию VIATOR/прошивки, если известны. Если один и тот же сеанс содержит ответ 0 и таймаут 1, это позволяет отдельно проверить адресацию/ответ 1 без повторного поиска причины в преамбуле.

Кодек проверен офлайн на **реальном ответе команды 0** из запроса. Ответ команды 1, используемый в автоматическом тесте, явно синтетический и не включён в APK. Проверка дампа не означает, что физическое чтение PV в новой сборке уже испытано.

## Ожидаемая приёмка

Команда 0 с четырьмя `FF` принята; производитель, версия и ID верны; команда 1 по уникальному адресу даёт реальную цифровую PV с единицей; полный лог доступен для копирования. После этого работа останавливается до отдельного задания на следующий этап.
