# HART-бро 0.4.0 — обход датчиков

Добавлен отдельный режим «Обход датчиков». Обычный мониторинг и история измерений сохранены; исправления Excel/PDF, подготовленные для 0.3.1, входят в 0.4.0 и отдельно не выпускаются.

## Работа обхода

Вкладка «Обход» → «Начать обход». Если VIATOR ещё не подключён, на вкладке «Связь» выбрать режим обхода, ранее сопряжённый коммуникатор и подтвердить подключение. Если коммуникатор уже готов к обычной сессии, его исправный RFCOMM передаётся обходу после отмены и завершения прежнего опроса; повторного подключения нет. Активную измерительную сессию сначала нужно явно сохранить/завершить либо отменить переход.

Один последовательный исполнитель читает команду 0 на коротком адресе 0. После идентификации использует длинный адрес: TAG 20 для HART 6/7 с резервом 13, настроенный диапазон 15, номер сенсора 14, номер окончательной сборки 16. HART 5 не требует команды 20. По умолчанию обход не выполняет измерительные 1/3/8/9 и диагностические 48/50. Все существующие чтения обычного мониторинга сохранены: **0, 1, 3, 8, 9, 13, 15, 20, 48, 50**; новые — **14, 16**. Запись отсутствует.

Интервал после завершения обмена выбирается 0,5 / 1 / 2 с, по умолчанию 1 с; один запрос — до 1,5 с, без повторной попытки в рамках запроса. Это целевой интервал обнаружения, не обещание прочитать весь паспорт за секунду. Необязательная команда без ответа добавляет до 1,5 с. Явный ответ «команда не поддерживается» запоминается для этого ID в текущем соединении. Набор паспорта читается при смене прибора, повторном обнаружении после двух пропусков, по кнопке и раз в 30 с при постоянном присутствии. Команда 0 продолжает обнаружение между чтениями.

Снятие щупов и отсутствие HART-ответов — состояние «Ожидание следующего датчика», без аварийного HART recovery и без разрыва исправного Bluetooth. Предыдущие строки остаются. Новый прибор добавляется автоматически; повторный ID обновляет свою строку. Протокольные ошибки не создают фиктивных приборов.

Только физическая ошибка RFCOMM или закрытый транспорт запускает восстановление Bluetooth с единым пределом 60 с и обратным отсчётом. После соединения ожидается любой следующий датчик; прежний прибор не требуется. Частично считанные поля сохраняются перед recovery. После исчерпания времени новые попытки прекращаются до решения пользователя: повторить подключение или завершить с сохранением/без сохранения.

## Паспортные поля

Каждое поле содержит значение, источник, команду, raw/HEX, время чтения, признак ручного ввода и подтверждение назначения. Производитель и код типа берутся из команды 0; неизвестная модель подписана, например, `Rosemount · тип 0x2662`. Название модели не угадывается по производителю.

Команда 14 декодирует трёхбайтовый unsigned номер сенсора и физические пределы; команда 16 — трёхбайтовый unsigned номер окончательной сборки. Эти номера остаются отдельными кандидатами с источником. Физические пределы 14 никогда не заменяют настроенный диапазон 15. HART Device ID не является заводским серийным номером. Редактируемая HART Date команды 13 не является подтверждённой датой изготовления.

`PassportProfile` — расширяемый интерфейс документированных интерпретаций. Для автоматического заводского поля нужны документированный профиль конкретного типа, соответствующий успешный ответ, исходный raw, подтверждение и документ. **В 0.4.0 нет выдуманных заводских соответствий для Метрана или Rosemount**: такой документации не предоставлено. Номера 14/16 и HART Date можно сверить со шильдиком в единственном аппаратном испытании. Перебора неизвестных команд производителя нет.

TAG, серийный номер, дата, марка и локальная подпись диапазона редактируются со шильдика/паспорта. Они получают источник «введено пользователем», сохраняются при автоматическом обновлении и не записываются в прибор. Номер — текст, включая ведущие нули. Дата — `15.07.2025`, `07.2025`, `2025` либо пусто; календарь проверяется, неизвестный день/месяц не дополняется.

Числовые границы и код единицы прочитанного диапазона хранятся отдельно от ручной подписи. Изменение диапазона при повторном чтении показывается отдельно и принимается только кнопкой пользователя.

Ключ строки — производитель / тип / HART Device ID. Нулевые/пустые/заполненные FF идентификаторы помечаются для проверки; повторное сомнительное совпадение, несколько строк с одинаковым ключом или изменившиеся номера 14/16 создают несопоставленное чтение. Оно не перезаписывает строку. Можно подтвердить существующую строку либо создать отдельную. Разделение доступно вручную и после сохранения. Подтверждение относится к текущему присутствию прибора; после нового подключения совпадение проверяется снова. Два физически разных прибора с полностью одинаковыми идентификационными данными автоматически отличить невозможно.

## Ведомость и фон

Временная ведомость едина для обхода; измерительные сессии/графики для каждого прибора не создаются. Foreground service владеет соединением и исполнителем, Activity получает состояние. Home, смена экрана и пересоздание Activity не запускают второй исполнитель. Уведомление показывает состояние/число строк/восстановление; wake lock удерживается во время работы, освобождается при ожидании решения и завершении.

Постоянное сохранение только вручную: «Сохранить обход» во время работы либо сохранение при завершении. Оно обновляет документ этого обхода и не останавливает опрос. «Сохранённые обходы» — отдельный список на вкладке «Обход», со своим открытием, локальным редактированием, экспортом и подтверждённым удалением. Измерительный журнал остаётся прежним. Ранее сохранённый документ остаётся после завершения без сохранения последующих изменений.

После изменения ведомости атомарно обновляется локальный временный черновик. После смерти процесса предлагается восстановление или подтверждённое удаление; соединение и служба скрыто не запускаются. Остановка службы сохраняет строки в памяти/черновике до решения. Невозможность записать черновик останавливает обход с сохранением строк в памяти и предложением экспортировать. Предел — 10000 строк, 10000 несопоставленных чтений, 32 МиБ на документ. Явное завершение освобождает соединение; переход из завершённого обхода в мониторинг открывает его заново в той же службе, без автоматического старта измерительной сессии.

## Excel и прежние отчёты

Ведомость обхода: настоящий `.xlsx`, один лист **«Приборы»**, первая строка — заголовки **TAG | Серийный номер | Дата выпуска | Тип / марка датчика | Диапазон**. Только пять видимых столбцов, одна строка на прибор, таблица с фильтром, закрепление A2, заданная ширина и читаемое оформление. Неизвестные поля пустые. Серийный номер и дата сохраняются текстом, диапазон компактный. Нет истории, HART ID, команд или HEX в дополнительных колонках. Несопоставленные чтения сохраняются в документе обхода, но не выдаются за подтверждённые строки Excel; приложение явно сообщает об этом.

Сохранение через Android SAF и отправка файла работают локально, включая активный обход; экспортируется неизменяемый снимок и опрос продолжается. Документ Office не требует интернета, макросов и внешних подключений.

Обычные измерительные сессии используют отдельный полный XLSX с ведомостью и историей PV/SV/TV/QV. Новый формат обхода не изменяет этот отчёт. [Сохранённые исправления экспорта](EXPORT_0.3.1.md): 269 реальных исходных значений → 68 точных временных строк, отдельные качества/источники, числовые значения и Excel-время; PDF — таблицы прибора/измерений/конфигурации/событий и единый график с отдельной легендой; CSV — дополнительный технический формат с явным разделителем. Обе книги используют общий низкоуровневый OOXML-писатель.
