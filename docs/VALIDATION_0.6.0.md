# Проверки HART-бро 0.6.0

Исходники: `feature/0.6.0-usb-walk`, база 0.5.3 `38ea403`. Пробная USB-интеграция без физического ЭнИ-406; аппаратная приёмка не заявляется.

## Измерение обхода до/после

Один и тот же `WalkTiming060Test.kt` выполнен на исходниках 0.5.3 и 0.6.0. Корутинные виртуальные часы: задержка каждого имеющегося ответа 150 мс, timeout 1500 мс, HART 7, используемый длинный TAG. Это проверка программного расписания, а не измерение скорости телефона/модема/перестановки щупов.

| Сценарий | 0.5.3 | 0.6.0 |
|---|---:|---:|
| Идентификация доступного датчика | 150 мс | 150 мс |
| Только конфигурация, все ответы | 600 мс: 20,15,14,16 | 450 мс: 13,15,20 |
| Только конфигурация, молчат ненужные 14/16 | 3500 мс, 2 таймаута | 450 мс, 0 таймаутов |
| Фактический период TX №0 без датчика | 2700 мс | 2100 мс |
| Timeout №0 | 1500 мс | 1500 мс |

Период TX включает timeout, паузу после завершения и прежние 200 мс тишины после неуспешного чтения. В исходниках 0.5.3 пауза была 1000 мс, в новом коде — 400 мс. Упомянутые в ТЗ 1200 мс не подставлялись вместо измеренного поведения исходной версии. При успешном ID дополнительной паузы перед конфигурацией нет. Основной HART 5 маршрут проверяется отдельно как 0→13→15; для HART 6/7 добавляется реально используемый 20.

Полный полевой обход пользователя (12 строк около 4:43) не сравнивался с виртуальным тестом: он включает ручное переключение. Задержка обнаружения после появления ответа, реальное время конфигурации, время экспорта на телефоне и накладные расходы должны быть измерены повторным полевым логом. В APK есть PERF для этих этапов, длительности/исходы команд, bounded retry, строки/совпадения ID и XLSX.

## Локальные проверки

JDK 21 / Gradle 8.13 / Android SDK 36. Команда:

```sh
./gradlew :hart-core:test :transport-usb:testDebugUnitTest :app:assembleDebug :app:assembleDebugAndroidTest :app:lintDebug --offline --no-daemon -Pkotlin.compiler.execution.strategy=in-process
./gradlew :hart-core:walkExampleReview -PwalkReviewDir=/tmp/hart-walk-review
python3 tools/validate_walk_xlsx.py /tmp/hart-walk-review
```

Окончательная локальная сборка успешна: **228 core JVM + 16 USB JVM = 244 теста, 0 failures/errors/skipped**. APK и инструментальный APK собраны, lint — 0 ошибок. Независимый openpyxl сравнил все 505 ячеек контрольной 100-строчной ведомости, пять колонок, десятичные ID и точность дат. Android CI будет указан после завершения.

Проверяются permission grant/deny/dismiss, поздний grant после отключения, отсутствие повторного permission-цикла, распознавание только upstream FTDI/WCH VID/PID, открытие scripted-порта/close/read/write errors/detach/reattach, fragments/4FF/нет XOR/поздний XOR, повтор на открытом порту, отмена/однократность 35, разделение статуса HART и транспорта. Политика разрешений и scripted SerialPortIo проверяют программную логику, не системный USB-контроллер и не настоящие диалоги телефона.

Android-набор сохраняет все 28 прежних сценариев и добавляет три USB-сценария: настоящий пустой UsbManager inventory без фиктивного порта/Activity recreate; HART timeout с открытым соединением и повтором; индикатор отключения и восстановление без запуска сессии. USB/HART-соединение этих двух последних тестов подменяется connectionFactory. Прежние три пятиминутных фоновых периода и проверки однократной записи сохранены.

## Аппаратная проверка

Ни реальные VID/PID пользовательского ЭнИ-406, ни UART baud/parity/RTS/DTR, ни успешный HART-обмен через физический модем здесь не подтверждены. Нет испытания установки поверх телефона пользователя. Драйверы FTDI и WCH CH34x включены по таблицам USB Serial 3.11.0, без произвольного VID/PID mapping; поддержка контроллера не сертифицирует ревизию ЭнИ.

[Документация и пошаговый аппаратный план](USB_0.6.0.md) · [Изменения](CHANGES_0.6.0.md). Ограничения профилей нуля/допустимых единиц/HART Date/Device ID из 0.5.3 сохранены.
