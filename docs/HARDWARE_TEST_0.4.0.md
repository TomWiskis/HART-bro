# Единый аппаратный сеанс HART-бро 0.4.0

Цель — один последовательный опыт с Android 16, VIATOR, Метраном-150 и доступным вторым прибором, желательно контрольным Rosemount HART 5. Все действия только чтение. Переставлять щупы лишь на разрешённых HART-точках по правилам объекта, не разрывая действующие измерительные цепи.

До начала: вручную сохранить важные измерительные сессии; установить опубликованный APK поверх 0.3.0 без удаления/очистки данных. Записать модель телефона/Android, VIATOR, питание/режим экономии. Сверить шильдики двух приборов и разрешение на подключение. Не менять их настройки ради проверки.

1. **Первое подключение.** Сопрячь VIATOR средствами Android; разрешить Bluetooth и уведомления. В «Обходе» нажать «Начать обход», на «Связи» выбрать VIATOR и один раз подтвердить подключение. Для начала можно оставить щупы снятыми: ожидается «Ожидание следующего датчика», исправный Bluetooth, пустая ведомость и отсутствие аварийного диалога.
2. **Метран-150.** Подключить щупы в разрешённой точке. Без нажатия опроса должна появиться одна строка. Сверить производителя/тип/HART revision/Device ID с фактическим прибором и диапазон команды 15 со штатными сведениями. В техническом раскрытии сохранить/сфотографировать ответы 14 и 16 и сопоставить номера с номером сенсора, сборки и заводским номером на шильдике. Отсутствующее заводское поле должно оставаться пустым. Не ожидать автоматического названия модели или заводской даты без документированного профиля.
3. **Ручные сведения.** Указать тестовый TAG, серийный номер с ведущими нулями, марку и дату известной точности (день/месяц/год). Проверить маркировку «вручную». Нажать повторное чтение; ручные поля должны остаться. Это локальные правки ведомости. Физические пределы 14 не должны заменять настроенный диапазон 15.
4. **Снятие щупов.** Снять щупы в безопасном порядке. После таймаута запроса должно быть ожидание следующего датчика, прежняя строка остаётся, нет HART recovery на 60 с, VIATOR не переподключается. Подождать не менее двух попыток обнаружения.
5. **Второй прибор.** Подключить второй датчик. Без кнопок старта/завершения должна появиться вторая строка с его идентификацией/диапазоном. Для HART 5 отсутствие команды 20 допустимо. Сохранить 14/16 и сопоставление со шильдиком; неподдерживаемая команда не должна прерывать обход.
6. **Возврат к Метрану.** Повторить снятие/подключение первого прибора. В ведомости две строки; ручные сведения первой сохранены. Если приборы имеют одинаковые ID/неоднозначные номера, проверить явное предложение выбрать существующую строку или разделить, без тихой перезаписи. Не изменять ID датчиков для создания такого случая.
7. **Фон.** При подключённом приборе нажать Home, открыть другое приложение и вернуться; затем выключить экран минимум на пять минут и вернуться. Проверить наличие уведомления, сохранность обеих строк, актуальность повторного обнаружения/чтения и отсутствие второго соединения. После каждого этапа перестановка щупов должна по-прежнему обнаруживаться автоматически. Зафиксировать фактическое поведение телефона, не приписывая возможный сбой заранее ОС или питанию.
8. **Bluetooth.** Если допустимо в условиях испытания, отдельно прервать Bluetooth VIATOR, не затрагивая измерительную цепь. Ожидается только Bluetooth recovery с одним пределом 60 с. Восстановить доступность модема: допускается ожидание любого следующего датчика, строки не теряются. Если не восстановлено за 60 с, должны быть ручной повтор подключения и завершение/сохранение. Отсутствие щупов само по себе такую процедуру не вызывает.
9. **Excel во время обхода.** Сохранить XLSX и отправить через стандартный Android выбор. Опрос/обнаружение должны продолжаться. В Microsoft Excel проверить один лист «Приборы», ровно пять заголовков, две строки приборов, фильтр, закрепление первой строки, отсутствие дополнительных технических колонок; неизвестные поля пустые, номер с нулями и точность даты сохранены. Повторить экспорт после локальной правки и проверить изменение только нового файла. Файл можно редактировать в Excel; обратного импорта в приложение нет.
10. **Постоянная ведомость.** Сохранить обход вручную, продолжить проверку, завершить с сохранением. Открыть в списке сохранённых обходов, проверить поля/происхождение, локальную правку и повторный экспорт. Удаление пробной ведомости проверить сначала отменой, затем подтверждением. Сохранённые обычные измерительные сессии не должны изменяться.
11. **Обычный мониторинг.** После явного завершения обхода подключиться для мониторинга; READY ещё не создаёт сессию. Начать её вручную, проверить PV/SV/TV/QV/единицы/качество/график и сохранение, затем открыть прежнюю сессию и экспортировать XLSX/PDF/CSV. В PDF проверить читаемость таблиц и легенды без наложения шкал. У завершённого обхода не должно оставаться своего исполнителя опроса.
12. **Результаты.** До очистки HEX сохранить полный TXT с первой идентификацией, всеми 14/16, снятием/сменой/возвратом приборов, фоном и recovery. Прислать TXT, оба новых XLSX (при необходимости без чувствительных TAG), PDF обычной сессии, сведения о телефоне/VIATOR/датчиках, сравнение 14/16 со шильдиками и список отклонений с временем. Старые реальные CSV/PDF с UUID `148d023e-8504-47ef-98a8-e3f5faba7954` уже учтены; дополнительный ZIP искать не нужно.

После выпуска разработка приостановлена до результатов этого испытания. Изменение диапазона в датчике, запись TAG/даты/номера, калибровка, сброс статусов, multidrop и USB в этот этап не входят.
