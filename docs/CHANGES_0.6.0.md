# Изменения 0.6.0

- USB Host/OTG для ЭнИ-406 через отдельный транспорт и общий HART-клиент; Bluetooth Classic SPP/RFCOMM VIATOR сохранён.
- Выбор транспорта и реального USB-порта, дескрипторы, разрешения Android, явные UART-настройки с указанием источника, ошибки открытия/чтения/записи и отключения. Подключение второго устройства не переключает активного владельца.
- Общий признак `transportConnected` отделён от ответа HART во всех режимах, включая настройку диапазона. Отключение гасит индикатор сразу, HART-таймаут сохраняет исправное соединение. Восстановление/проверка ID и 60-секундный предел сохраняются.
- Обход читает 0→13→15; для HART 6/7 затем 20, поскольку длинный TAG реально отображается. 14/16 больше не читаются без документированного профиля, которому они нужны. Только для таймаутов обязательных 13/15 допускается один дополнительный запрос; код «не поддерживается» и физическая потеря транспорта не повторяются как паспортные чтения.
- Пауза после неуспешного обнаружения — 400 мс после завершения запроса, timeout остаётся 1500 мс. Последовательный actor/mutex не создаёт перекрывающихся запросов или очереди таймеров. Успешный ID сразу переходит к конфигурации.
- После подтверждённого отсутствия/повторного появления существующего ID используется выбор существующей или новой UUID-строки. Одиночный пропуск сохраняет присутствие. Незавершённое решение нельзя обойти очередным перечитыванием.
- XLSX сохраняет один лист и пять колонок. Колонка «Серийный номер» теперь всегда содержит unsigned decimal Device ID, включая старые ведомости: 000001→1, BF2C34→12528692. Старые ручные паспортные значения остаются в хранилище, не превращаются в ключ и не подменяют экспортируемый Device ID. Остальные поля, их происхождение и точность дат сохранены.
- Обычный HEX содержит полные кадры/ошибки/ключевые события, без создания RX-CHUNK на каждый фрагмент. Подробный режим сохраняет фрагменты. Добавлены длительности/исходы команд, discovery/config, повторов, добавления строк, решения по совпадению ID, начала/конца обхода и XLSX.
- Записи используют прежние транзакции, подтверждения и проверку результата. Команда 35 отправляется один раз, при потере ACK — проверочное чтение. Для USB дополнительно требуется успешное чтение конфигурации и измерений перед записью.

- Единый справочник определяет `0x0026 / 0x2662 / Rev 9` как **Метран-150R** во всех карточках, обходе, экспорте и диагностике. Исходный код Rosemount и зарегистрированный производитель Emerson сохраняются; источник — реестр FieldComm Group. Другие ревизии не получают неподтверждённое имя.
- Начальная идентификация — до трёх последовательных попыток через исправный транспорт с паузой 350 мс, без вложенных тройных проб в обходе. Разделены таймауты: начальный 3500 мс, поиск обхода 1500 мс, обычное чтение 2500 мс, восстановление ID 3500 мс при общем пределе 60 с. Различаются отсутствие данных, неполный кадр, XOR, длина, адрес, команда, ответ прибора и физический транспорт. Проверка XOR и поддержка 4 FF сохранены.
- [Универсальная установка нуля](ZERO_0.6.0.md): стандартная 43 доступна и неизвестной модели давления после двухэтапного подтверждения. Пустой data, актуальный адрес, одна запись, контроль PV и известный допуск/разрешение. Без подтверждения измерением выводится отдельный исход. Запись 35 не используется для нуля и не повторяется.
- [Приём без запросов / импорт HEX](PASSIVE_HART_0.6.0.md): отдельный владелец соединения, запрет TX, временные метки, декодирование и XOR, сравнение «до/после», сохранение сценариев. Видимость чужого обмена на реальном Android-модеме пока не подтверждена.
- Исправлена гонка закрытия/повторного открытия настройки диапазона: отложенное закрытие относится только к прежнему владельцу и не закрывает новую операцию.

Application ID, прежние сессии, ведомости и журнал 35 сохранены, данные не очищаются. Журнал параметров читает старый формат 1, новые операции сохраняет в формате 2 с подробностями нуля. Device ID остаётся только для чтения, дата производства — редактируемое HART Date без выдуманной заводской даты. Быстрая карточка и режимы сохранены; визуального редизайна нет.

Аппаратная совместимость ЭнИ-406 и UART-профиль пользовательского экземпляра пока не подтверждены: [источники, настройки и полевой план](USB_0.6.0.md). [Исходное ТЗ](SPEC_0.6.0.md) · [дополнение](SUPPLEMENT_0.6.0.md).

## Компоненты

Новый модуль `transport-usb`: `UsbHostController` (UsbManager, inventory/permission/open/reattach), `EniUsbDrivers` (upstream FTDI/WCH ID-таблицы), `UsbPermissionGate` (один запрос на выбранное подключение), `UsbHartTransport`/`SerialPortIo` (байтовый обмен, отмена и ресурсы), `UsbPortSettings` и `UsbReadQualification`. Библиотека — отдельный локальный модуль `usb-serial`.

Переработаны общий `HartTransport` и `HartClient` (статус, отключение, метрики и подробность RX), прежний `BluetoothSppTransport` (реализация общих status/disconnect), `SessionController`, страница USB и значок транспорта, состояния `MonitoringEngine`/`WalkEngine`/`RangeEngine`, `PassportReader`, `WalkCatalog` и `WalkXlsx`. Android-сервис и приложение сохраняют одного владельца соединения при передаче между режимами. Добавлены программные USB/обходные тесты, Android USB UI/recreate/recovery и одинаковый benchmark для исходной и новой версии.
