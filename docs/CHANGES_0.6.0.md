# Изменения 0.6.0

- USB Host/OTG для ЭнИ-406 через отдельный транспорт и общий HART-клиент; Bluetooth Classic SPP/RFCOMM VIATOR сохранён.
- Выбор транспорта и реального USB-порта, дескрипторы, разрешения Android, явные UART-настройки с указанием источника, ошибки открытия/чтения/записи и отключения. Подключение второго устройства не переключает активного владельца.
- Общий признак `transportConnected` отделён от ответа HART во всех режимах, включая настройку диапазона. Отключение гасит индикатор сразу, HART-таймаут сохраняет исправное соединение. Восстановление/проверка ID и 60-секундный предел сохраняются.
- Обход читает 0→13→15; для HART 6/7 затем 20, поскольку длинный TAG реально отображается. 14/16 больше не читаются без документированного профиля, которому они нужны. Только для таймаутов обязательных 13/15 допускается один дополнительный запрос; код «не поддерживается» и физическая потеря транспорта не повторяются как паспортные чтения.
- Пауза после неуспешного обнаружения — 400 мс после завершения запроса, timeout остаётся 1500 мс. Последовательный actor/mutex не создаёт перекрывающихся запросов или очереди таймеров. Успешный ID сразу переходит к конфигурации.
- После подтверждённого отсутствия/повторного появления существующего ID используется выбор существующей или новой UUID-строки. Одиночный пропуск сохраняет присутствие. Незавершённое решение нельзя обойти очередным перечитыванием.
- XLSX сохраняет один лист и пять колонок. Колонка «Серийный номер» теперь всегда содержит unsigned decimal Device ID, включая старые ведомости: 000001→1, BF2C34→12528692. Старые ручные паспортные значения остаются в хранилище, не превращаются в ключ и не подменяют экспортируемый Device ID. Остальные поля, их происхождение и точность дат сохранены.
- Обычный HEX содержит полные кадры/ошибки/ключевые события, без создания RX-CHUNK на каждый фрагмент. Подробный режим сохраняет фрагменты. Добавлены длительности/исходы команд, discovery/config, повторов, добавления строк, решения по совпадению ID, начала/конца обхода и XLSX.
- Записи используют прежние транзакции, подтверждения и проверку результата. Команда 35 отправляется один раз, при потере ACK — проверочное чтение. Для USB дополнительно требуется успешное чтение конфигурации и измерений перед записью.

Application ID и форматы существующих сессий/ведомостей/журналов не меняются. Данные не очищаются. Ограничения нуля, записи Device ID, неподтверждённых единиц и трактовки HART Date из 0.5.3 сохраняются. Визуального редизайна нет.

Аппаратная совместимость ЭнИ-406 и UART-профиль пользовательского экземпляра пока не подтверждены: [источники, настройки и полевой план](USB_0.6.0.md). [Исходное ТЗ](SPEC_0.6.0.md).
