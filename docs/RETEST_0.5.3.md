# Полевые испытания 0.5.3

APK устанавливается поверх прежней версии с тем же сертификатом. Сохраните нужные ведомости/отчёты штатным экспортом. Для проверки настройки используйте прибор с разрешёнными изменениями и известным исходным состоянием.

1. Подключите ранее сопряжённый VIATOR и откройте «Монитор». Не запускайте сессию: должны остаться карточка, TAG, десятичный Device ID, заполненная дата, диапазон. PV/ток/график не выводятся. На HEX допустимы лёгкие команды 0; непрерывных 1/3/9 нет. Успешная связь остаётся зелёной.
2. Снимите щупы и верните их. Bluetooth остаётся подключённым, датчик становится красным; после ответа возвращается зелёный. Полностью отключите питание VIATOR: индикатор Bluetooth должен погаснуть, восстановление показывать оставшееся время только пока идут попытки. Возвращение адаптера должно восстановить связь без перезапуска приложения.
3. Подключите другой датчик без измерительной сессии. Примерно через 1–2 секунды после доступного ответа должны обновиться Device ID и конфигурация, не создавая историю PV. Неизвестная модель остаётся с кодом типа. При открытой диагностике старые сведения сбрасываются, предлагается обновить её.
4. Нажмите информационную часть: открывается диагностика с новыми чтениями. Карандаш справа открывает только диапазон. Неполная/отсутствующая дата в быстрой карточке не занимает места.
5. В диагностике измените TAG, Long Tag (при наличии) и дату с шильда. До подтверждения записи не должно быть. Проверьте повторным чтением и внешним коммуникатором, что целевое поле изменилось, остальные поля команды 13 сохранились. Откройте журнал. Отключение связи во время записи должно дать подтверждённый чтением либо неподтверждённый результат; повторная команда записи автоматически не отправляется.
6. Device ID / Meter ID — один десятичный серийный номер, доступный для чтения. Он не подменяется номером сборки или Message.
7. В диапазоне текущая единица должна быть выбрана сразу. Первый ввод заменяет прежнее число целиком, знак/запятая доступны. Выберите неподтверждённую единицу: она остаётся видимой, но кнопка записи блокируется с объяснением. Обычная запись в разрешённой единице — ровно одна команда 35, затем 0/15 и сравнение фактического диапазона.
8. Ноль на **подтверждённом профиле Viatran 970, HART 5, DEV_REV 2**: задайте физический ноль (для абсолютного давления нужен эталонный вакуум), откройте подтверждение, проверьте предупреждение о влиянии на автоматику. После подтверждения — одна команда 43 и три PV-чтения. Показания должны уложиться в объявленный допуск, журнал — отразить фактические значения. На остальных моделях неподтверждённая команда не отправляется. Не путать датчик Viatran 970 с Bluetooth-модемом VIATOR.
9. Нажмите «Начать измерительную сессию»: только теперь появляются PV, ток, график и новая история. Завершите сессию: приложение возвращается к лёгкому опросу, без продолжения записи измерений.
10. В сессии прокрутите график назад и оставьте на минуту: положение и ширина окна сохраняются. Измените масштаб: следование само не включается. Перемотайте к настоящему времени: следование включается. Поверните экран / пересоздайте Activity, сверните приложение и заблокируйте экран: активная сессия/подтверждённая запись не дублируются.
11. В истории раскройте записи диапазона, TAG/даты/нуля. Удалите одну запись с подтверждением: остальные остаются; новых HART-команд нет.
12. Выполните прежний обход A → нет прибора → B → A с ручными паспортными полями и экспортом XLSX. Логика обхода и происхождение паспортных данных должны остаться прежними. USB на этом этапе не используется.

При отклонениях сохраните HEX TXT, журнал операции и модель/шильд прибора. Особо полезны полный ответ команды 0 и документация HART конкретной ревизии для расширения профилей нуля и единиц.
