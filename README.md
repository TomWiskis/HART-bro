# HART-бро — Android HART Communicator

Прототип **этапа 1**: Android 10+, Kotlin, Compose / Material 3, Bluetooth Classic RFCOMM/SPP, HART-команды **0** и **1**. Интерфейс на русском, светлая и тёмная темы. Интернет и регистрация приложению не нужны; разрешение `INTERNET` отсутствует.

## Сборка

Нужны JDK 21, Android SDK Platform 36, Build Tools 36.0.0. Установите их через Android Studio SDK Manager или `sdkmanager`:

```sh
sdkmanager "platforms;android-36" "build-tools;36.0.0" "platform-tools"
```

Примите лицензии SDK. Укажите расположение SDK в переменной `ANDROID_HOME` либо в неотслеживаемом `local.properties`:

```properties
sdk.dir=/absolute/path/to/android-sdk
```

Из корня репозитория:

```sh
./gradlew :hart-core:test :app:assembleDebug :app:lintDebug --no-daemon
```

Windows: `gradlew.bat` с теми же аргументами. Gradle Wrapper 8.13 закреплён с SHA-256 дистрибутива. AGP 8.13.2, Kotlin 2.2.21, compile/target SDK 36, min SDK 29. При первой сборке нужен доступ к Google Maven, Maven Central и дистрибутиву Gradle; работа установленного приложения полностью автономна.

APK: `app/build/outputs/apk/debug/app-debug.apk`. Это отладочная сборка с тестовой подписью, не релиз для распространения через Google Play.

## Установка APK

1. Включите на телефоне режим разработчика и USB-отладку, подтвердите доверие компьютеру.
2. Подключите телефон и проверьте его командой `adb devices`.
3. Выполните `adb install -r app/build/outputs/apk/debug/app-debug.apk`.
4. Откройте «HART-бро». Альтернатива — скопировать APK на телефон и разрешить его установку из выбранного файлового менеджера.

При конфликте подписи существующей установки используйте исходный ключ подписи либо предварительно удалите старое приложение с согласия владельца телефона.

## Реализовано

- Чтение списка сопряжённых устройств, фильтр VIATOR, выбор из нескольких модемов; возможность показать переименованный модем. Первое сопряжение выполняется штатными средствами Android.
- Разрешение `BLUETOOTH_CONNECT` на Android 12+. Поиск в эфире, BLE и геолокация не используются.
- Диалог согласия перед каждым новым подключением. Secure RFCOMM с UUID SPP `00001101-0000-1000-8000-00805F9B34FB`, отмена соединения и таймаут подключения 15 секунд.
- Формирование запросов, короткая/длинная адресация, преамбулы, накопительный потоковый разбор, проверка XOR, длины, адреса и команды. Четыре `FF` в ответе принимаются с предупреждением, без ослабления проверки полного кадра. Поддержаны асинхронные STX/ACK/burst и 0–3 expansion bytes.
- Идентификация командой 0 на адресе опроса **0**, primary master; дальнейший запрос 1 по уникальному длинному адресу. Разбор идентификации HART 5–7 и цифровой IEEE-754 PV с единицами, статусом и временем получения ответа.
- Производитель: «Метран» для `0x0099`, Rosemount для `0x0026`; неизвестные коды сохраняются. Полный тип модели показан без потери старших битов, торговое название модели не угадывается. Единицы давления/температуры имеют символы и русские названия; неизвестные единицы сохраняются кодом. Версия HART отделена от ревизий устройства и ПО; флаги состояния расшифровываются на экране и в журнале.
- Сериализация запросов, таймаут HART 2,5 секунды, максимум две попытки безопасного чтения. Никаких команд записи, произвольного терминала или автоматической калибровки.
- Разовое чтение при подключении; кнопка «Считать снова». Нет искусственных промежуточных значений и пересчёта 4–20 мА.
- Диагностика полных `TX-FRAME`/`RX-FRAME` и исходных `RX-CHUNK`, кода ответа, статуса, времени обмена, ошибок и неполных кадров: последние 256 событий в памяти, явное копирование пользователем. Автоматического постоянного журнала нет.

## Пока не реализовано

Этапы 2–5: непрерывный мониторинг, графики, восстановление за 60 секунд, фоновая служба, журнал/Room, PDF/CSV, сравнения, конфигурирование, запись, шаблоны, карточки параметров, полноценный терминал, профили и DD/EDD. При сворачивании прототип закрывает соединение; после возврата требуется новое подтверждение. Поворот экрана сохраняет текущий ViewModel и соединение.

Multidrop, адреса опроса кроме 0, HART до ревизии 5, PSK и extended commands пока не поддерживаются. USB OTG/ЭнИ-406 оставлены на будущее; сейчас только Bluetooth VIATOR. После потери связи/ошибки соединение закрывается, последнее измерение убирается. Это ограничение этапа 1, а не реализованное автоматическое восстановление.

Особенности инициализации конкретной прошивки VIATOR требуют проверки по руководству производителя и на аппаратуре: прототип отправляет обычные HART-кадры в SPP-поток, без предполагаемых AT-команд, управляющих байтов или недокументированных обходов RFCOMM.

Веб-страницы производителя, FieldComm Group и Android были недоступны из исходной сетевой политики облачной среды. Доступ к ним запрошен в черновике настройки. Android API дополнительно проверен по официальному JavaDoc из установленного SDK 36 (`android-stubs-src.jar`): SPP, блокирующий `connect`, отмена через `close`, разрешение `BLUETOOTH_CONNECT`. Документация VIATOR и HART с указанных сайтов не прочитана, аппаратная совместимость не подтверждена. Перед лабораторным испытанием проверьте требования питания, нагрузки, режима модема и безопасности по официальным инструкциям вашего оборудования.
