# HART-бро 0.6.0 — USB OTG, устойчивость HART и установка нуля

**[Скачать APK 0.6.0 для испытаний](https://github.com/TomWiskis/HART-bro/raw/refs/heads/downloads/hart-bro-0.6.0-debug.apk?download=1)** · Android 10+, прежняя подпись, versionCode 12. Для закрытого репозитория нужен вход в GitHub.

Добавлен USB Host для ЭнИ-406: обнаружение реальных VID/PID/интерфейсов, FTDI и WCH CH34x через **usb-serial-for-android 3.11.0**, разрешения Android, явные UART-настройки и диагностика. USB и Bluetooth VIATOR используют общий HART-клиент. Быстрый просмотр, сессии, диагностика, обход, экспорт и поддержанные записи доступны через оба транспорта; сессия запускается отдельно. HART-таймаут не означает потерю USB. Команда 35 остаётся однократной с проверочным чтением.

**Физический ЭнИ-406 здесь не подключался. VID/PID и UART-настройки пользовательского экземпляра не подтверждены.** В интерфейсе нужно ввести настройки из документации или работающей программы; 1200 бит/с HART-линии не назначаются автоматически UART-порту. Вариант без БП требует внешнего питания датчика. Сначала испытать чтение; USB-запись дополнительно требует успешных 0/13/15 и трёх измерительных ответов.

Обход: 0→13→15, затем используемый длинный TAG 20 для HART 6/7; лишние 14/16 исключены из стандартного маршрута. Timeout 0 сохранён 1500 мс, пауза после неудачи — 400 мс. Повторный ID после отсутствия требует выбора строки, один пропуск новую строку не создаёт. В XLSX серийный номер — десятичный Device ID (000001→1, BF2C34→12528692), внутренние UUID и старые ручные данные сохранены.

Добавлены до трёх начальных попыток идентификации без закрытия исправного соединения и раздельные таймауты. Причины ошибок HART различаются, XOR проверяется строго, реальные неполные/повреждённые ответы из журнала входят в регрессию. `0x0026 / 0x2662 / Rev 9` показывается как **Метран-150R** с сохранением исходных кодов Rosemount.

**Установка нуля** через стандартную 43 доступна и неизвестной модели датчика давления: подготовка условий, чтение PV, отдельное подтверждение, одна запись и контроль PV по указанному допуску/разрешению. Без известных критериев или измерения результат явно остаётся неподтверждённым. Есть [отдельный отчёт](docs/ZERO_0.6.0.md).

На «HEX» доступны приём без собственных HART-запросов, импорт внешнего HEX, сравнение «до/после» и сохранение сценариев. **Пассивная видимость чужого обмена у конкретных VIATOR/ЭнИ-406 аппаратно не проверена**; возможности Windows VSPCF не выдаются за испытание Android. [Источники и аппаратный план](docs/PASSIVE_HART_0.6.0.md).

[Изменения](docs/CHANGES_0.6.0.md) · [USB: источники, ограничения и полевой план](docs/USB_0.6.0.md) · [Проверки и измерения](docs/VALIDATION_0.6.0.md) · [ТЗ](docs/SPEC_0.6.0.md). ## Быстрый просмотр и настройка 0.5.3

Карточка показывает производителя/модель, TAG, десятичный Device ID, заполненную дату и диапазон. Нажатие на информацию открывает диагностику; карандаш отдельно открывает диапазон. В фоне команда 0 проверяет присутствие примерно раз в 1,5 с; замена датчика обновляет конфигурацию. **PV, ток и измерительная история включаются только кнопкой «Начать измерительную сессию».** Потеря RFCOMM запускает восстановление ранее выбранного VIATOR, состояние Bluetooth отделено от HART.

В диагностике редактируются короткий/длинный TAG и дата производства (редактируемое HART Date, можно заполнить по шильду). Перед записью проверяются прибор, исходное значение и защита; после одной записи — повторная идентификация и чтение. Device ID / Meter ID по уточнению пользователя означает серийный номер и доступен для чтения: универсальной команды изменения этого ID нет. Final Assembly Number в новом интерфейсе не используется; обход оставлен прежним.

Кнопка «Установить ноль» требует подтверждённого профиля модели/ревизии, подтверждения приложенного нулевого давления и проверки PV после одной команды 43. **Первый документированный профиль — Viatran 970, HART 5, Device Revision 2. Для остальных моделей команда заблокирована до подтверждения поддержки.** Неизвестный тип Метран 0x9972 не переименовывается в неподтверждённую модель.

Диапазон сохраняет компактный ввод в строку и выделение старого числа. Выбирается любой код единицы; неподтверждённая прибором единица блокирует запись. Команда **35 по-прежнему отправляется один раз** с проверкой фактического диапазона.

Журнал показывает диапазон, TAG, дату и ноль с результатом проверки и удалением отдельных записей. График сохраняет выбранное положение/масштаб; масштабирование не включает следование самопроизвольно, временная шкала фиксирует свою область во время перетаскивания. Ожидание актуальности измерений увеличено до max(15 с, 4 периода).

## Повторная идентификация датчика

HART-таймаут команды 0 сохраняет исправное Bluetooth-соединение. Нажмите **«Повторить опрос датчика»** после подключения датчика: используется открытый RFCOMM, а при его потере приложение самостоятельно подключается к ранее выбранному VIATOR. Перезапуск приложения не нужен. Прибор должен определиться до отдельного запуска измерительной сессии.

Неполный ответ без XOR не считается успешным; поздние фрагменты очищаются перед новым чтением. Пересоздание Activity сохраняет управление повтором. Команда **35 не повторяется**: после её отправки по-прежнему требуется проверка фактического результата. Все возможности 0.5.0 сохранены.

## Настройка диапазона

**«Настроить диапазон»** в карточке подключённого прибора открывает самостоятельный экран. Читаются текущие значения 15, пределы/Minimum Span 14 и идентификация/TAG. Мониторинг или обход приостанавливается с сохранением данных и соединения. Два поля используют исходную единицу; проверяются Float32, порядок, физические пределы, минимальная ширина и защита записи.

**Ввод → Установить → Да, записать → Проверить.** Подтверждение показывает ID/TAG, старый/новый диапазоны и влияние на 4–20 мА. Пароля, лабораторного режима и ограничений по назначению оборудования нет. Типизированная команда **35** передаётся ровно один раз, затем выполняются 0/15. Округление, предупреждение, отказ и неизвестный результат отображаются отдельно; только факт отправки не означает успех.

Перед TX сохраняется устойчивое намерение, далее — ответ/код/статус/фактический диапазон и ошибки. История операций и ручной TXT доступны на «Связи». После таймаута/обрыва/перезапуска доступны только проверочные чтения, автоматического повтора 35 или отката нет. Home, экранная блокировка и recreate не дублируют операцию. Подтверждённый результат возвращает прежний активный опрос; пользовательская пауза сохраняется, при неопределённости автоматического продолжения нет.

Диалоги завершения обхода/перехода/подтверждения имеют вертикальные действия, ограниченную высоту и прокрутку описания. Отмена и Android Back сохраняют обход.

[Команда 35 и таблица кодов](docs/HART35_0.5.0.md) · [Компоненты и ограничения](docs/CHANGES_0.5.0.md) · [Один аппаратный сеанс](docs/HARDWARE_TEST_0.5.0.md).

## Обход датчиков

- Один раз подтвердить подключение к VIATOR, затем последовательно переставлять щупы. Приборы обнаруживаются автоматически, добавляются в единую ведомость и при повторном обнаружении обновляют свою строку. Между приборами не нужны кнопки старта/завершения сессии.
- TAG 13/20, настроенный диапазон 15, номер сенсора 14 и номер окончательной сборки 16. Необязательные неподдерживаемые поля не прерывают обход. Производитель и код типа получаются из команды 0; конкретная модель показывается только при документированном соответствии.
- Снятие щупов — «Ожидание следующего датчика» с сохранением Bluetooth. Только потеря RFCOMM запускает восстановление Bluetooth до 60 с; ведомость сохраняется и после восстановления допускается любой следующий датчик.
- Локальное уточнение TAG, заводского номера, даты, марки и подписи диапазона. Ручные сведения помечаются и сохраняются при повторных чтениях. Дата поддерживает день, месяц или только год; серийные номера сохраняют ведущие нули. HART Device ID, номер сенсора/сборки и редактируемая HART Date автоматически не становятся заводскими паспортными сведениями.
- Подтверждение изменения диапазона, проверка сомнительных совпадений ID и ручное разделение строк. Постоянное сохранение ведомости вручную; отдельный список сохранённых обходов, редактирование и подтверждённое удаление. Черновик можно восстановить после сбоя по собственному решению.
- Настоящий XLSX: один лист **«Приборы»**, ровно пять колонок **TAG | Серийный номер | Дата выпуска | Тип / марка датчика | Диапазон**, фильтр и закреплённая первая строка. Неизвестные поля пусты. Локальное сохранение/отправка доступны и во время обхода.

[Пример Excel на 100 **искусственных** приборов](docs/examples/TEST-ONLY-walk-100-devices.xlsx) · [Проверка структуры и значений](docs/examples/walk-xlsx-validation.json) · [Подробности и ограничения обхода](docs/CHANGES_0.4.0.md).

## Обычный мониторинг и отчёты

Сохранены отдельное подключение/READY без истории, явный старт измерительной сессии, цифровые PV/SV/TV/QV и исходные качества/единицы, общий график с разрывами, пауза/продолжение, интервалы 1/2/5/10 с и ручные снимки. Архивы 0.2.0/0.2.1/0.3.0 открываются без перезаписи. В журнале — названия/комментарии, поиск, сравнение конфигураций и подтверждённое удаление. Обычная сессия остаётся привязана к одному прибору с прежним восстановлением до 60 с.

Исправления экспорта, подготовленные для 0.3.1, включены в 0.4.0. Основной отчёт измерительной сессии — **XLSX**: один лист с ведомостью и историей, одна строка на точную временную метку, числовые PV/SV/TV/QV и даты Excel, отдельные качества и источники. В реальном контрольном примере все **269 значений сохраняются в 68 временных строках**. PDF A4 содержит таблицы прибора/измерений/конфигурации/событий и единый график с отдельной легендой шкал. CSV остаётся дополнительным техническим экспортом: UTF-8 BOM, `sep=;` или `sep=,`, выбор разделителя в интерфейсе и имени файла. [Описание и реальные контрольные файлы](docs/EXPORT_0.3.1.md).

Оба режима работают через видимую foreground service, отдельную от Activity. Home/возврат и пересоздание Activity не запускают второй опрос. Уведомление показывает состояние; HEX-журнал до 16 МиБ сохраняется в TXT, подробные RX-CHUNK включаются отдельно. После смерти процесса скрытого рестарта соединения нет.

Чтения **0, 1, 3, 8, 9, 13, 14, 15, 16, 20, 48, 50** и одна отдельно подтверждённая запись **35**. Обычный измерительный резерв 9→3→1 и потоковый декодер длины/XOR сохранены. Запись TAG/даты/номера/демпфирования, калибровка, сброс флагов, произвольные команды, multidrop, USB OTG и ЭнИ-406 в этот выпуск не входят. INTERNET permission отсутствует.

## Установка и первое использование

1. В 0.5.1 вручную сохраните важную текущую сессию/ведомость. Установите **APK 0.5.2 поверх 0.5.1 без удаления приложения и очистки данных**; допустимо `adb install -r hart-bro-0.5.2-debug.apk`. Application ID и прежний сертификат сохранены, versionCode — 10. Для опубликованных 0.2.0/0.2.1 сертификат также совместим. Утраченный ключ 0.1.1 не восстановлен. Произвольный APK из CI может иметь другой debug-ключ: для обновления используйте опубликованную ссылку.
2. Сопрягите VIATOR средствами Android, разрешите Bluetooth и уведомления. Для обхода откройте «Обход» → «Начать обход», выберите VIATOR на «Связи» и подтвердите подключение. При готовом соединении повторное подтверждение не требуется. Снятые щупы допустимы: приложение будет ожидать следующий датчик.
3. Переставляйте щупы только на разрешённых HART-точках. Просматривайте последнюю карточку и накопленные строки; при необходимости уточняйте паспортные поля со шильдика. «Сохранить обход» создаёт/обновляет постоянную ведомость и продолжает работу; «Экспорт в Excel» сохраняет снимок файла. «Завершить обход…» предлагает сохранение или удаление временного черновика.
4. Для обычных измерений выберите мониторинг на «Связи», дождитесь READY и отдельно нажмите «Начать сессию». Снимки и полный XLSX/PDF/CSV доступны в измерительном «Журнале». При переключении из активного режима прежние данные сначала завершаются по вашему решению.

Измерительная временная история ограничена 64 МиБ. Ведомость обхода — до 10000 строк, документ до 32 МиБ; временный черновик обхода восстанавливается только по выбору пользователя. Постоянный журнал пополняется только вручную. Старые измерительные файлы не конвертируются в ведомости. Необработанные неоднозначные чтения видны в приложении и сохраняются в документе обхода; Excel содержит сопоставленные строки.

## Сборка и проверки

JDK 21 с `javac`, Android Platform 36, Build Tools 36.0.0 и platform-tools; Gradle Wrapper 8.13, AGP 8.13.2, Kotlin 2.2.21.

```sh
sdkmanager "platforms;android-36" "build-tools;36.0.0" "platform-tools"
./gradlew :hart-core:test :app:assembleDebug :app:assembleDebugAndroidTest :app:lintDebug --no-daemon
./gradlew :app:connectedDebugAndroidTest --no-daemon
./gradlew :hart-core:walkExampleReview -PwalkReviewDir=/tmp/hart-walk-review
python3 tools/validate_walk_xlsx.py /tmp/hart-walk-review
```

openpyxl нужен только для независимой проверки на компьютере, не приложению. При сохранённом кэше Gradle доступен `--offline`. Для прежнего локального ключа используется `HARTBRO_DEBUG_KEYSTORE=/absolute/path/debug.keystore`; ключ в Git не входит. Сохраняйте JVM proxy/CA облачной среды, не отключайте TLS-проверки. APK: `app/build/outputs/apk/debug/app-debug.apk`.

GitHub Actions использует setup-android v4, очистку ненужных toolchains, диагностику диска и API 36 AVD userdata 2 ГиБ. CI проверяет фактическое выполнение всех ожидаемых Android-тестов без ошибок/пропусков, включая прежние три пятиминутных периода обычного мониторинга. Имитируемый транспорт и контрольные файлы присутствуют только в тестовых APK/ресурсах.

**Запись 35 по-прежнему требует аппаратного испытания конкретного прибора и его токового выхода.** Предыдущие CSV/PDF пользователя уже использованы для регрессии экспорта. После публикации работа остановлена до результатов [одного комплексного испытания](docs/HARDWARE_TEST_0.5.0.md).
