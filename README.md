# HART-бро 0.3.0

Android-приложение для чтения цифровых HART-измерений через Bluetooth Classic SPP / Pepperl+Fuchs VIATOR. HART 5–7, polling address 0. Основной аппаратный прибор — Метран-150 HART 7. Application ID: `ru.hartbro.app`.

**[Скачать готовый APK 0.3.0](https://github.com/TomWiskis/HART-bro/raw/refs/heads/downloads/hart-bro-0.3.0-debug.apk?download=1)**

Репозиторий закрытый: откройте ссылку в браузере после входа в GitHub с доступом к репозиторию. Исторические APK [0.2.1](https://github.com/TomWiskis/HART-bro/raw/refs/heads/downloads/hart-bro-0.2.1-debug.apk?download=1) и [0.2.0](https://github.com/TomWiskis/HART-bro/raw/refs/heads/downloads/hart-bro-0.2.0-debug.apk?download=1) сохранены в ветке `downloads`.

## Возможности

- Подтверждённое подключение к ранее сопряжённому VIATOR и идентификация без создания сессии. Отдельная кнопка «Начать сессию»; перед каждой новой проверкой повторно читается идентификатор прибора. Несколько отдельных сессий через одно исправное Bluetooth-соединение.
- Цифровые PV/SV/TV/QV, исходные единицы и качество, интервалы 1/2/5/10 с; пауза/продолжение, сохранение без остановки опроса, завершение с сохранением либо без него. Значения не рассчитываются из 4–20 мА.
- Общий график с числовыми шкалами, независимыми масштабами несовместимых единиц, легендой/выбором серий/точек, масштабированием/сдвигом/автоследованием. Настроенный диапазон команды 15 — одной строкой справа сверху. Паузы, потери, плохое качество и смена единиц прерывают линии.
- Журнал ручных снимков: название, комментарий, поиск по TAG/ID/названию, сортировка, график/конфигурация без подключения датчика, подтверждаемое отдельное/множественное удаление и очистка. Старые архивы 0.2.0/0.2.1 читаются без перезаписи.
- Локальные PDF A4 и CSV через Android выбор файла/отправку. PDF содержит прибор, диапазон, статистику по всем исходным принятым точкам, общий график, события и комментарий. CSV — полные исходные записи с UTC, качеством и командами, UTF-8, выбор `;`/`,`, десятичная точка; пропуски не подменяются нулями.
- Частичный снимок стандартной конфигурации: 0 — идентификация; 13/20 — TAG/описание; 15 — настроенный диапазон/демпфирование/другие доступные поля; 48 — диагностика; 50 — назначения переменных. Сохраняются источник и исходные байты. Сравнение двух архивов или архива с последними текущими прочитанными настройками. Отсутствующее поле — «Нет данных»; текущие давление/температура не являются настройками.
- Видимая foreground service, отдельное от Activity владение обменом, wake lock на время работы, восстановление максимум 60 с с проверкой прибора. Исправный Bluetooth при HART-ошибках сохраняется. Возврат Activity не создаёт новую сессию.
- Полный рабочий HEX до 16 МиБ с первой идентификацией, ручной TXT/share, подробный RX-CHUNK по выбору. ACTIVITY/SERVICE/PROCESS/STATE/BLUETOOTH, причины остановки, последние TX/RX/измерение. В UI последние 512 событий; Clipboard ограничен 500 кБ, полный TXT сохраняется отдельно.

Только безопасные чтения **0, 1, 3, 8, 9, 13, 15, 20, 48, 50**. Сохранены потоковый декодер, проверка длины/XOR, совместимость с четырьмя FF реального Метрана и измерительный резерв 9→3→1. Нет записи, команды 38, сброса статусов, калибровки, USB OTG, Terminal, автоматического обхода или восстановления конфигураций. Нет INTERNET permission.

## Обновление и первое использование

1. В 0.2.1 вручную сохраните важную текущую сессию. Установите опубликованный APK 0.3.0 **поверх 0.2.1 без удаления приложения и очистки данных**; допустимо `adb install -r hart-bro-0.3.0-debug.apk`. Существующий сертификат опубликованных 0.2.0/0.2.1 сохранён, versionCode повышен до 5. Ключ 0.1.1 утрачен: для неё совместимое обновление не обещается. APK из произвольного CI-run может иметь другой debug-ключ — используйте опубликованную ссылку.
2. Сопрягите VIATOR средствами Android, разрешите Bluetooth и уведомления. На вкладке «Связь» подтвердите подключение; дождитесь правильного ID/готовности. Периодический опрос пока не идёт.
3. На вкладке «Монитор» нажмите «Начать сессию». Проверьте измерения/качество/диапазон. Для постоянной проверки нажмите «Сохранить сессию»; повторное сохранение создаёт отдельный снимок, не прекращая опрос.
4. Во вкладке «Журнал» откройте проверку, измените название/комментарий или экспортируйте PDF/CSV. Закреплённое «К списку» и системная «Назад» возвращают в список.
5. Завершите сессию с сохранением либо без него. Исправный Bluetooth остаётся подключённым для следующей явной сессии; отдельно можно отключить коммуникатор.

Снимки сохраняются только по действию пользователя. Временная история ограничена 64 МиБ; при заполнении требуется решение. Уничтожение службы сохраняет временную историю до решения пользователя, но после смерти всего процесса несохранённые временные файлы очищаются при следующем запуске. Android/производитель телефона могут остановить процесс; скрытого рестарта после force-stop нет.

## Сборка и проверки

Полный JDK 21 с `javac`; Android Platform 36, Build Tools 36.0.0, platform-tools. Gradle Wrapper 8.13 с закреплённой контрольной суммой, AGP 8.13.2, Kotlin 2.2.21.

```sh
sdkmanager "platforms;android-36" "build-tools;36.0.0" "platform-tools"
./gradlew :hart-core:test :app:assembleDebug :app:assembleDebugAndroidTest :app:lintDebug --no-daemon
./gradlew :app:connectedDebugAndroidTest --no-daemon
```

Инструментальные проверки выполняются на Android 16/API 36, включая три реальных пятиминутных интервала проверки новых данных. CI сохраняет диагностику диска, очистку ненужных runner toolchains и AVD userdata 2 ГиБ; результаты XML проверяются на наличие всех ожидаемых тестов, отсутствие ошибок и пропусков. При сохранённом кэше доступен `--offline`. Для прежнего локального ключа задаётся `HARTBRO_DEBUG_KEYSTORE=/absolute/path/debug.keystore`, сам ключ не входит в Git. В прокси-среде сохраняйте настройки JVM proxy/CA, проверки TLS не отключайте. APK: `app/build/outputs/apk/debug/app-debug.apk`.

Автоматические Android-тесты используют транспорт только из `androidTest`; его нет в основном APK. Аппаратная работа 0.2.1 с Метраном подтверждена пользователем, **0.3.0 требует нового испытания**. Точная причина прежнего сбоя в фоне не доказана одними временными отметками; исправления и диагностика описаны отдельно.
