# HART-бро — Android HART Communicator

**0.2.0 — кандидат для аппаратного испытания.** Kotlin, Android 10+ (min 29, target 36), Compose / Material 3, Bluetooth Classic RFCOMM/SPP. Работа установленного приложения автономна, разрешения INTERNET нет. Application ID остаётся `ru.hartbro.app`.

## Возможности 0.2.0

- Подтверждённое подключение к ранее сопряжённому VIATOR, адрес HART 0; сохранён потоковый парсер и приём четырёх FF с предупреждением, проверкой длины/XOR.
- Только команды чтения 0, 1, 3, 8, 9, 48, 50. Первоначальное определение возможностей; HART 7: запрос 9 с кодами 246–249. HART 6: коды из 50, если доступны; HART 5: команда 3. Неподдерживаемые способы отключаются на текущую сессию, переход 9 → 3 → 1.
- PV/SV/TV/QV без догадок о физическом назначении, исходные единицы/коды, статусы качества и время получения. Из тока не вычисляются давление/температура; ток, когда прочитан командой 3, подписан отдельно как значение, сообщённое датчиком.
- Один последовательный цикл; интервалы 1/2/5/10 с (по умолчанию 2 с), без накопления просроченных запросов. Пауза/продолжение.
- Один график, общая ось времени, независимые масштабы Y, цвета, скрытие серий, масштабирование, перемещение, следование и просмотр точек. При большом объёме показаны первая/минимальная/максимальная/последняя точки временных корзин. В архиве остаются все исходные измерения.
- Ошибки, паузы, пропуски/плохое качество и смена единиц прерывают линии. Нули и интерполяция вместо потерянных данных не используются.
- После трёх последовательных ошибок HART либо немедленно при I/O-разрыве — восстановление максимум 60 с. Исправный Bluetooth сохраняется. После возврата проверяется уникальный ID и производитель; другой прибор не добавляется в прежнюю историю. Таймаут/другой прибор требуют решения пользователя.
- Foreground service `connectedDevice`, уведомление и ограниченные по времени возобновляемые wake lock. Сворачивание/блокировка экрана не завершают сессию. Android может остановить процесс: автоматического рестарта после этого нет.
- Временный журнал до 64 МиБ во внутреннем хранилище; при заполнении требуется решение. Только ручные постоянные снимки, в том числе повторные, просмотр и удаление с подтверждением. Завершение удаляет только временную историю. После гибели процесса оставшиеся временные файлы удаляются при следующем запуске.
- Последние 512 технических/сессионных событий в памяти, копирование по запросу. Полный бесконечный HEX на диск не записывается.

## Сборка

Нужны полный **JDK 21** с `javac`, SDK Platform 36, Build Tools 36.0.0, platform-tools. Gradle Wrapper 8.13 закреплён SHA-256, AGP 8.13.2, Kotlin 2.2.21.

```sh
sdkmanager "platforms;android-36" "build-tools;36.0.0" "platform-tools"
# ANDROID_HOME должен указывать на SDK; допустим локальный local.properties.
./gradlew :hart-core:test :app:assembleDebug :app:lintDebug --no-daemon
```

При сохранённом кэше используйте `--offline`. В прокси-среде Gradle нужны JVM-параметры `https.proxyHost`/`https.proxyPort` (и HTTP), с сохранённым доверенным CA. Проверки TLS и контрольной суммы не отключать. APK: `app/build/outputs/apk/debug/app-debug.apk`. Ключ debug-подписи не хранится в Git; для повторного выпуска с тем же сертификатом нужен тот же локальный ключ. CI сам по себе не гарантирует совпадения debug-ключа с опубликованным APK.

## Первое использование

1. На отдельном телефоне установите 0.2.0 без удаления 0.1.1 на основном телефоне. Сопрягите VIATOR штатными средствами Android.
2. Разрешите Bluetooth и уведомления; подтвердите подключение в приложении.
3. Во вкладке «Монитор» проверьте ID, значения, качество, период, график; для архива нажмите «Сохранить сессию».
4. При завершении выберите сохранение либо удаление временной истории. Сохранённые снимки находятся во вкладке «Журнал».

При отказе в уведомлениях Android допускает FGS, но уведомление с запросом решения может отсутствовать в обычной шторке. Для аппаратного испытания разрешите уведомления. Постоянный журнал локальный; удаления/очистки данных приложения избегайте.

## Границы версии

Нет записи, команды 38, калибровки, сброса статусов, изменения токового выхода, USB OTG, Terminal, PDF/CSV, сравнения/шаблонов. Ревизии HART 5–7, polling address 0. Никаких недокументированных команд модему. Реальное чтение PV Метрана-150 версией 0.1.1 подтверждено пользователем; новое чтение нескольких переменных, фон и восстановление **0.2.0 ещё не испытаны на оборудовании**. Нельзя считать отсутствие диагностических флагов подтверждением полной исправности датчика.
